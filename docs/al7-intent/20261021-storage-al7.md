Stage 1, substep 2 from CLAUDE.md: Storage layer. Postgres 16 + PostGIS + pgvector in docker-compose (dev DB plus a separate test DB), Knex migrations and Objection models. The schema stores what the substep 1 client returns (contracts/wikimapia-client.schema.ts): PlaceSummary from `box` and PlaceDetails, Comment and Tag from `place.getbyid`.
- places: Wikimapia place id as primary key, name/title, description, url, flags (is_building, is_region, is_deleted), parent id, outline as PostGIS geometry (SRID 4326) plus a center point, location fields. A place can exist with only summary data before its details are fetched, so record when details were last fetched.
- comments: keyed by (place id, num), nested replies stored flat with a reference to the parent comment, author name kept for attribution, no user_ip.
- tags: separate tables (tags + place_tags), since Stage 2 filters by category.
- Repository functions to upsert a listing page and a place's details (idempotent: re-saving the same data changes nothing), and to read a place back with its comments and tags.
- Enable the `vector` extension in a migration, but do NOT add embedding columns; substep 4 adds them.
- Crawl progress tracking belongs to substep 3, not here.
Tests that need a database run against the test DB from docker-compose.

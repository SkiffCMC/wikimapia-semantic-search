## 0. Scope and Fixed Points

This feature adds the **Storage component**: a Postgres 16 + PostGIS + pgvector database in docker-compose (one server, a Development Database and a Test Database), versioned Knex migrations, Objection models, and a repository (`PlaceStore`) that saves and reads what the Wikimapia Client returns. It does not call Wikimapia, OpenAI or any HTTP service. It has no embedding columns and no crawl progress (AC-5).

Fixed by AL5, not to be changed by AL3/AL2:

| Item | Value |
|---|---|
| Entry point 1 | `src/db/place-store.ts` exports `createPlaceStore: CreatePlaceStoreFn` |
| Entry point 2 | `src/db/schema-setup.ts` exports `createSchemaSetup: CreateSchemaSetupFn` |
| Public types | `PlaceStore`, `PlaceStoreOptions`, `WriteHook`, `SchemaSetup`, `SchemaSetupOptions`, all `*Result` types, `StoreFailure`, `StoredPlace`, `PlaceShapes`, ... (all from `contracts/storage.schema.ts`) |
| Table names | `STORE_TABLES`: `places`, `comments`, `tags`, `place_tags` |
| Extensions | `REQUIRED_EXTENSIONS`: `postgis`, `vector`, enabled by a migration step and disabled by its undo |
| SRID | `WGS84_SRID` = 4326 |
| Env vars | `TEST_DATABASE_URL` (tests), `DATABASE_URL` (development); the test DB name ends in `_test` |
| Helpers to reuse (never re-implement) | `buildWikimapiaLink`, `outlineShapeRing`, `findCommentRuleIssues`, `SavePlaceDetailsInputSchema`, `SaveListingPageInputSchema`, `PlaceRefInputSchema`, `TagRefInputSchema`, `StoreConfigSchema`, `ReadPlaceValueSchema`, `PlaceShapesSchema`, `StoreStructureSchema` |

**Approved contract choices (user, 2026-10-21), designed in as-is:** `fetchedAt` is a whole-second UTC ISO string and reads back in exactly that form; a closed 3-point outline (A, B, A) gets no outline shape (`outlineShapeRing` returns `undefined`); `undoAll` disables `vector` (and `postgis`, section 2.6); `emptyStore` refuses with `store_unavailable` unless the connected database name ends in `_test`; a summary-only read-back has `status: 'summary_only'` with empty `tags` and `comments`.

**Single source of truth.** Every `src/db/*` module imports schemas, types and helpers from `../../contracts/storage.schema` and `../../contracts/wikimapia-client.schema` (migrations from `../../../contracts/...`). AL2 must not copy or redefine any of them.

**Code style (`.agrules` section 5).** Relative imports are extensionless (`from './types'`). Every type alias and interface declared in `src/db/` lives in `src/db/types.ts` and is imported with a top-level `import type { ... } from './types'`. Types inferred from internal Zod row schemas are declared in `types.ts` as `z.infer<typeof XRowSchema>` with `import type { XRowSchema } from './rows'` (a `typeof` on a type-only import is valid). Contract `z.infer` types are imported from the contract, never re-exported. `unknown` appears only where `.agrules` section 5 allows it (caught errors and their `cause`, raw Knex/pg results parsed with Zod on the next line, validator parameters that check untrusted input); section 4 "Refactor note (2026-10-22)" lists every remaining use with its justification. Column maps, the pre-gate shapes value and the `PlaceStore` method parameters are typed (section 1.3).

**HTTP framework:** not needed (no server in this feature). The open decision in `CLAUDE.md` stays open.

### 0.1 Decisions made by this design (for the orchestrator to record in `CLAUDE.md`)

| Decision | Choice |
|---|---|
| Database image | Custom image `docker/postgres/Dockerfile`: `FROM postgis/postgis:16-3.6` (Debian 13 trixie, PostgreSQL 16, PostGIS 3.6, PGDG source `trixie-pgdg`) plus apt package `postgresql-16-pgvector` (pgvector 0.8.x, verified `0.8.7-1.pgdg13+1`). Not `16-3.5`: it is Debian 11 bullseye, whose `bullseye-pgdg` source now returns 404; no `16-3.5-bookworm`/`-trixie` tags exist, and apt-archive is not used. The image's own `10_postgis.sh` init script is removed so that extensions are created only by migration (`.agrules` section 3) |
| Databases | One Postgres server (compose service `postgres`), two databases: `wikimapia` (Development) and `wikimapia_test` (Test), user `wikimapia`, published on `127.0.0.1:5433` |
| Test env | `vitest.config.ts` reads `.env.test` (gitignored; template `.env.test.example` is committed) into `test.env`; shell env wins. No `globalSetup` |
| Migrations for tests | Each DB test file applies them itself in `beforeAll` via `createSchemaSetup(...).apply()` (idempotent; the contract test already does this) and empties the store in `beforeEach` via `emptyStore()` |
| Test parallelism | `fileParallelism: false` for the whole Vitest run, because DB test files share one Test Database and the contract undoes all migrations mid-file (AC-2, AC-4) |
| Migration loading | A static Knex `migrationSource` (list of imported modules), no file-system migration directory and no `knexfile` (avoids Knex's dynamic `import()` of absolute Windows paths, works the same under Vitest and `tsx`) |
| Big integers | Every whole number that comes from Wikimapia is `bigint` in Postgres and is parsed back to a JS `number` by a per-connection int8 type parser that rejects unsafe integers |

### 1.2 Call flow

```
PlaceStore method (input)
  1. validate input with the contract schema           -> invalid_data (no DB touched; AC-51 holds even for an unreachable store)
  2. db configured?  (StoreConfigSchema ok and Knex created)  -> else store_unavailable 'Place Store is not configured'
  3. try { run the operation }                           (reads: one read-only REPEATABLE READ transaction;
                                                          saves: one READ COMMITTED transaction, section 1.5)
     catch (anything) -> unavailableFrom(error)          (fixed message + safe code only; AC-57)
  4. reads: gate the assembled value with its contract schema (ReadPlaceValueSchema, PlaceShapesSchema, ...)
           gate failure -> store_unavailable 'stored data failed the read-back check'
  5. resolve { ok: true, value } | { ok: false, failure }  (never rejects)

Listing Save (in the transaction)                         Details Save (in the transaction)
  a. dedupe: last occurrence wins, first-appearance order   a. pg_advisory_xact_lock(placeId)
  b. pg_advisory_xact_lock(id) for each id, ascending        b. loadDetailsState (place row, its comments,
  c. loadListingState (rows for these ids)                      its links + tag titles, titles of input tags)
  d. planListingSave (pure)                                  c. planDetailsSave (pure)
  e. execute planned writes in order through the Writer      d. execute planned writes in order through the Writer
  f. report = plan outcomes                                  e. report = [{ placeId, outcome }]
```

### 1.4 Detailed behaviour per subsystem

#### 1.4.1 Factories (`place-store.ts`, `schema-setup.ts`; AC-51, AC-57)

- `createPlaceStore(options)` **never throws**. It copies only `connectionString` into a fresh object and runs `StoreConfigSchema.safeParse` on it (the schema is strict; `onWrite` must not be passed to it). On success it calls `createDb(connectionString, POOL_MAX_STORE)` inside `try`; if that throws, the store is "not configured". `onWrite` is kept as given.
- A not-configured store still returns a full `PlaceStore`. Each method first validates its input (invalid input is `invalid_data` even here), then resolves `store_unavailable` with `Place Store is not configured: connection string is missing or unusable` (no value echoed).
- `createSchemaSetup(options)` follows the same pattern with `POOL_MAX_SETUP`.
- `close()` on both: `destroyQuietly(db)`; idempotent; never rejects. After `close()` the instance is not reused by any contract test; calls after close may resolve `store_unavailable`.
- Every public method body is wrapped in `try/catch`; anything unanticipated becomes `store_unavailable` via `unavailableFrom(error, '<action>')`. Public methods return `Promise<...>` and must never reject.

#### 1.4.2 Connection (`connection.ts`)

```
createDb(connectionString, poolMax) = knex({
  client: 'pg',
  connection: {
    connectionString,
    connectionTimeoutMillis: CONNECT_TIMEOUT_MS,
    statement_timeout: STATEMENT_TIMEOUT_MS,
    types: { getTypeParser: (oid, format) => oid === pg.types.builtins.INT8 ? parseSafeInt8 : pg.types.getTypeParser(oid, format) },
  },
  pool: { min: 0, max: poolMax },
  acquireConnectionTimeout: ACQUIRE_TIMEOUT_MS,
})
parseSafeInt8(text): n = Number(text); if !Number.isSafeInteger(n) throw new Error('int8 value is not a safe integer'); return n
```

- Following the project convention (top-level `import type`, as in `src/wikimapia/`), use the default import `import knex from 'knex'` plus a separate `import type { Knex } from 'knex'` rather than an inline `type` specifier. Do **not** use `import { knex } from 'knex'`: knex 3.3.0 has no `exports` field and under plain Node ESM (`tsx` scripts) only `default` is exposed, so the named form fails with "does not provide an export named 'knex'" (it works under Vitest only through Vite interop). Import pg as `import pg from 'pg'` (CommonJS default import; `module: preserve` enables `esModuleInterop`). See section 5 for the full import rule.
- The int8 parser is **per connection** (the `types` option), not `pg.types.setTypeParser` (no global mutation).
- `timestamptz` is never returned raw: reads format it in SQL (section 1.4.8), so no Date parsing is involved.
- Knex's pg pool propagates connection errors to the waiting query (`ECONNREFUSED` on `127.0.0.1:1` fails fast, AC-57).

#### 1.4.3 Failures (`failures.ts`; AC-15, AC-38, AC-39, AC-53 .. AC-58)

- `invalidData(issues)`: `{ kind: 'invalid_data', message: describeStoreIssues('Invalid data', issues), issues }`, issues capped at `MAX_REPORTED_ISSUES` (20, reuse from `src/wikimapia/issues`) and never empty.
- Issue mapping reuses `toFailureIssues` from `src/wikimapia/issues` (paths kept, messages from Zod, **no input values**; never enable `reportInput`). `describeStoreIssues` formats the first issue with `formatIssuePath` (empty path -> `(whole input)`), plus ` (+N more)`.
- `unavailableFrom(error, action)`: `{ kind: 'store_unavailable', message }` where message is the fixed template `Place Store unavailable: ${action} failed` plus ` (${code})` when `safeErrorCode(error)` returns one. `safeErrorCode` reads `error.code` (and `error.cause.code`) and accepts only `/^E[A-Z0-9_]+$/` (Node errno, e.g. `ECONNREFUSED`) or `/^[0-9A-Z]{5}$/` (SQLSTATE, e.g. `3D000`, `28P01`). **Never** copy `error.message`, `error.detail`, `error.where`, the SQL text or any binding: Knex puts SQL and values into its messages, pg puts user and database names into its messages, and the `onWrite` test hook throws arbitrary text.
- Secret check: no failure produced anywhere contains the connection string, the password or `postgres://` (AC-57). The design guarantees this by construction (fixed templates); no regex scrubbing is needed.

#### 1.4.4 Input validation (`validate.ts`; AL6 rule 1, AC-15, AC-38, AC-39, AC-51, AC-53 .. AC-55)

- `validateListingInput`: `SaveListingPageInputSchema.safeParse(input)`. Zod paths are already into the input (`['places', 1, 'placeId']`, `['places', 2, 'url']`, `['places', 0, 'location', 'lon']`; `undefined` input -> path `[]`).
- `validateDetailsInput`:
  ```
  try r = SavePlaceDetailsInputSchema.safeParse(input)
  catch -> invalidData([{ path: [], message: 'input does not have the shape of a Details Save' }])
  if r.success -> ok
  issues = toFailureIssues(r.error.issues)
  d = PlaceDetailsSchema.safeParse(isRecord(input) ? input.details : undefined)
  if d.success:
     for rule of findCommentRuleIssues(d.data):
        for issue in issues where samePath(issue.path, ['details', ...rule.path]):
           attach commentNum = rule.commentNum, placeId = rule.placeId (only keys that are defined)
  return invalidData(issues)
  ```
  This gives AC-38 (`commentNum: 5, placeId: 55` at `['details','comments',0,'replies',0,'replies',0,'placeId']`) and AC-39 (`commentNum` on the later duplicate's `num`). A Commenter IP at any depth is an unknown key of the strict Comment shape; Zod reports the key name only (AC-54). The `try` guards against a contract refinement running on malformed data.
- `validatePlaceRef` / `validateTagRef`: `PlaceRefInputSchema` / `TagRefInputSchema`; `NaN`, `0`, `-3`, `1.5` give path `['placeId']` (AC-51).
- Only the **parsed** value (`r.data`) is used afterwards, never the raw input.

#### 1.4.5 Listing Save (`plan.ts`, `save-listing.ts`; AC-7 .. AC-15, AC-63, D1, D6)

`dedupeListing`: walk the page; keep the **first index** of each Place ID for the report order and the **last value** for the data (AC-13).

`planListingSave(places, state)` for each deduped summary `s`, in order:

| Stored row | Comparison | Write | Outcome |
|---|---|---|---|
| none | | `insert_summary` | `created` |
| summary-only (`details_fetched_at` null) | `name`, `wikimapia_url`, the 6 location numbers, outline pairs (exact `===` on every number) | if any differs: `update_summary` (all summary columns, centre point, outline shape) | `updated` / `unchanged` |
| detailed | `wikimapia_url` only (D1) | if it differs: `update_link` | `updated` / `unchanged` |

A Listing Save never touches tags, links, comments or any details column, and never touches name, location or outline of a detailed place (AC-11, AC-63). An empty page plans nothing and reports `{ places: [] }` (AC-12). Listing totals (`page`, `pageSize`, `totalFound`) are validated and dropped (AC-14).

`saveListing(db, page, onWrite)`:
```
places = dedupeListing(page.places); if places is empty -> return { places: [] }   (no transaction needed)
db.transaction(async trx => {
  for id of sorted ascending distinct ids: await trx.raw('select pg_advisory_xact_lock(?::bigint)', [id])
  state = await loadListingState(trx, ids)
  plan = planListingSave(places, state)
  writer = createWriter(onWrite)
  for w of plan.writes: await writer.run(<one statement for w>)
  return { places: plan.outcomes }
})
```
Statements: `insert_summary` -> `PlaceModel.query(trx).insert({ place_id, ...summaryColumns(s), centre_point: centrePointSql(trx, s.location), outline_shape: outlineShapeSql(trx, s.outline) })`; `update_summary` -> `PlaceModel.query(trx).findById(id).patch({...same without place_id})`; `update_link` -> `patch({ wikimapia_url })`. One statement per planned write.

#### 1.4.6 Details Save (`plan.ts`, `save-details.ts`; AC-16 .. AC-39, AC-40 .. AC-43, AC-64 .. AC-69, D1 .. D6)

`flattenComments(comments)`: pre-order depth-first walk; each Comment/Reply yields `{ comment, parentNum (null at top level), position (index among its siblings) }`. Pre-order guarantees a parent is written before its replies.

`planDetailsSave({ details: D, fetchedAt: F }, state)`:

```
changed = false
// place row
if state.place is undefined:            place = { kind: 'insert', wikimapiaUrl: buildWikimapiaLink(D.placeId) }   outcome base 'created'
else if state.place is summary-only:     place = { kind: 'update_details' }; changed = true
else if detailsColumns(D) differs from the row (name<-title, description, 3 flags, parent, wikipedia, 6 location numbers,
        6 address items with absent == null, outline pairs):
                                         place = { kind: 'update_details' }; changed = true
else if row.details_fetched_at_text !== F: place = { kind: 'update_fetched_at' }      // D3: does NOT set changed
else                                     place = undefined
// the stored wikimapia_url is never changed by a Details Save (D6, AC-20, AC-31)

// tags: dedupe D.tags by id, FIRST occurrence wins (position and title); AL5 does not fix this case beyond AC-43
for (t, i) of dedupedTags:
   if !state.tagTitles.has(t.id) or state.tagTitles.get(t.id) !== t.title: tagUpserts.push(t); changed = true   // AC-42
   link = state.links.find(tagId == t.id)
   if !link:                                   linkWrites.push(insert t.id, i); changed = true
   else if link.presence !== 'present' or link.position !== i: linkWrites.push(update t.id, i); changed = true
for link of state.links (ascending tag id) not in dedupedTags and presence 'present': goneLinks.push(tagId); changed = true

// comments
for flat of flattenComments(D.comments):
   row = state.comments.find(num == flat.comment.num)
   if !row:  commentWrites.push(insert flat); changed = true
   else if any of (13 value fields, parent_num, presence != 'present', position) differs: commentWrites.push(update flat); changed = true
for row of state.comments (ascending num) whose num is not in D and presence 'present': goneComments.push(num); changed = true
     // a Gone row keeps every value and its parent_num (AC-27, AC-66, AC-67)

outcome = state.place undefined ? 'created' : changed ? 'updated' : 'unchanged'
tagUpserts sorted ascending by id (stable lock order across concurrent saves)
```

`saveDetails(db, input, onWrite)` runs in one transaction:
```
await trx.raw('select pg_advisory_xact_lock(?::bigint)', [placeId])
state = await loadDetailsState(trx, details); plan = planDetailsSave(input, state); writer = createWriter(onWrite)
1. place:   insert  -> PlaceModel.query(trx).insert({ place_id, wikimapia_url, ...detailsColumns(D, F), centre_point, outline_shape })
            update_details -> findById(id).patch({ ...detailsColumns(D, F), centre_point, outline_shape })
            update_fetched_at -> findById(id).patch({ details_fetched_at: F })
2. tags:    each upsert -> trx('tags').insert({ tag_id, title }).onConflict('tag_id').merge(['title'])   (race-safe)
3. links:   insert/update present links (position i) in input order; then each gone link: patch presence 'gone', position null
4. comments: insert/update in pre-order (presence 'present', position, parent_num); then each gone comment: patch presence 'gone', position null
return { places: [{ placeId, outcome }] }
```
Every statement goes through `writer.run(...)`. A save that changes nothing at all (same details, same `F`) writes nothing and calls the hook zero times (AC-21); any other save writes at least once.

Write count is deterministic for a given stored state and input (fixed order above), which the fault-injection loops of AC-15 and AC-56 rely on.

#### 1.4.7 Writer and fault hook (`writer.ts`; AC-15, AC-56)

```
createWriter(onWrite):
  count = 0
  run(statement): await statement; count += 1; if onWrite: await onWrite(count)
```
A synchronous throw or a rejection from `onWrite` propagates out of the transaction callback; Knex rolls the transaction back and rethrows; `place-store.ts` maps it to `store_unavailable` (`save failed part way and was rolled back`). Production code never passes `onWrite`. Advisory locks and `SELECT`s are not writes and are never counted.

#### 1.4.8 Read-back (`read.ts`, `mappers.ts`; AC-8, AC-16 .. AC-19, AC-34, AC-35, AC-40 .. AC-52, AC-59, AC-71, AC-72)

Reads that need more than one query run in `db.transaction(..., { isolationLevel: 'repeatable read', readOnly: true })` so they see one snapshot.

- **Place row:** select every column except the two geometries, plus `to_char(details_fetched_at AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS"Z"') AS details_fetched_at_text`. Parse with `PlaceRowSchema`. No row -> `{ found: false, placeId }` (AC-50).
- **Summary-only** (`details_fetched_at_text` null): `{ status: 'summary_only', placeId, name, wikimapiaUrl, location: { lon, lat, north, south, east, west }, outline: decodeOutline(row.outline), tags: [], comments: [] }`. Address columns are never read for it (they are null by the table check anyway).
- **Detailed:** `{ status: 'detailed', placeId, name, wikimapiaUrl, description, tags, isBuilding, isRegion, isDeleted, outline, location, comments, detailsFetchedAt }` with `parentPlaceId`, `wikipediaUrl` and the six address keys (`street`, `houseNumber`, `city`, `place`, `state`, `country`) attached **only when the column is not null** (`exactOptionalPropertyTypes`; AC-19, AC-24).
- **Tags** (`orderStoredTags`): links of the place joined with `tags.title`; present links ordered by `position`, then gone links ordered by `tag_id` (AC-72); each `{ id, title, presence }`.
- **Comments** (`buildStoredComments`): load all rows of the place; group children by `parent_num` (null = top level); each sibling list ordered present-by-`position`, then gone-by-`num` (AC-52); build recursively, each node `{ placeId, num, langId, author, authorUserId, [authorPhotoUrl], message, goodVotes, badVotes, isBlocked, isDeleted, postedAtEpochSeconds, moderatorUserId, [moderatorName], presence, replies }`. Defensive rule: any row not reachable from the top level (cannot happen with section 2.4's invariants) is appended at the top level after the others, so nothing stored is ever hidden (AC-71).
- **Gate:** the assembled value goes through `ReadPlaceValueSchema.safeParse`; failure -> `store_unavailable` (`stored data failed the read-back check`).
- **Shapes** (`readShapesValue`): one query returning `ST_SRID(centre_point)`, `GeometryType(centre_point)`, `ST_X(centre_point)`, `ST_Y(centre_point)`, `ST_SRID(outline_shape)`, `GeometryType(outline_shape)`; and, when `outline_shape` is not null, the ring via `SELECT ST_X(dp.geom), ST_Y(dp.geom) FROM ST_DumpPoints(ST_ExteriorRing(outline_shape)) dp ORDER BY dp.path[1]`. Map `'POINT'` -> `'Point'`, `'POLYGON'` -> `'Polygon'`. `outlineShape` is omitted when null (AC-48, AC-70). Gate with `ReadShapesValueSchema`. Coordinates come from `ST_X/ST_Y` (float8, exact), never from `ST_AsGeoJSON` (which rounds to 9 decimals by default).
- **Tag catalogue:** `SELECT tag_id, title FROM tags ORDER BY tag_id` (AC-40). **Links of a tag:** `... WHERE tag_id = ? ORDER BY place_id` (AC-41, AC-69). **Comment keys:** `... WHERE place_id = ? ORDER BY num`, `parentNum` only when not null (AC-35; unknown place -> `[]`). **Counts:** one statement with four `count(*)` sub-selects (int8 -> number via the parser; AC-7, AC-61).

#### 1.4.9 Map shapes (`geometry.ts`; AC-44 .. AC-48, AC-70, D4)

- `centrePointSql(db, { lon, lat })` = `db.raw('ST_SetSRID(ST_MakePoint(?, ?), 4326)', [lon, lat])`.
- `outlineShapeSql(db, outline)`: `ring = outlineShapeRing(outline)` (contract helper); `undefined` -> `null` (no shape: fewer than 3 points, or closed A, B, A); otherwise `db.raw('ST_SetSRID(ST_GeomFromGeoJSON(?), 4326)', [polygonGeoJson(ring)])`.
- `polygonGeoJson(ring)` = `JSON.stringify({ type: 'Polygon', coordinates: [ring.map(p => [p.lon, p.lat])] })`. `JSON.stringify` of a JS double gives the shortest round-trip text, so `ST_X/ST_Y` read back the identical double.
- Self-crossing outlines (bow tie, AC-47) are stored as given: PostGIS does not validate polygons on insert, and the design never calls `ST_MakeValid` or `ST_IsValid`.
- Shapes are recomputed whenever the summary or details columns are written (`insert_summary`, `update_summary`, `insert`, `update_details`), never on `update_link` or `update_fetched_at` (AC-11 shapes unchanged).

#### 1.4.10 Schema Setup (`schema-setup.ts`, `inspect.ts`, `migrations/`; AC-1 .. AC-6, AC-14, AC-61)

- Migration config passed to every call: `{ migrationSource, tableName: MIGRATION_TABLE }` with `MIGRATION_TABLE = 'knex_migrations'` (lock table `knex_migrations_lock`). No `directory`, no `loadExtensions`.
- `migrationSource`: `getMigrations` -> `Promise.resolve(MIGRATIONS)`; `getMigrationName(m)` -> `m.name`; `getMigration(m)` -> `{ up: m.up, down: m.down }`. `MIGRATIONS` is a literal array in the order of section 2.6. Step names are the file stems (e.g. `20261021_01_enable_extensions`). Each step runs in its own transaction (Knex default).
- `apply()`: `const [, log] = await db.migrate.latest(config)` -> `{ steps: log }` (empty when nothing pending, AC-3).
- `undoAll()`: `const [, log] = await db.migrate.rollback(config, true)` -> `{ steps: log }` (newest first; the contract test sorts, AC-4).
- `inspect()` (`readStructure`):
  - `appliedSteps`: `[]` if `knex_migrations` does not exist, else `SELECT name FROM knex_migrations ORDER BY id`.
  - `pendingSteps`: names in `MIGRATIONS` order that are not applied.
  - `enabledExtensions`: `SELECT extname FROM pg_extension ORDER BY extname` (includes `plpgsql`).
  - `availableExtensions`: `SELECT name FROM pg_available_extensions ORDER BY name` (AC-1).
  - `tables`: base tables of `current_schema()` from `information_schema.tables` (`table_type = 'BASE TABLE'`) except `knex_migrations` and `knex_migrations_lock`, ordered by name, each with its columns from `information_schema.columns` ordered by `ordinal_position` (`name` = `column_name`, `dataType` = `data_type`, `udtName` = `udt_name`). PostGIS's own `spatial_ref_sys` is a base table of the schema and is listed; it passes every structural check of AC-5, AC-6 and AC-14 (columns `srid`, `auth_name`, `auth_srid`, `srtext`, `proj4text`).
  - Gate with `StoreStructureSchema`.
- `emptyStore()`: `name = currentDatabaseName(db)` (`SELECT current_database()`); if `!isTestDatabaseName(name)` -> `store_unavailable` `Refusing to empty a database whose name does not end in "_test"` (approved choice). Otherwise one statement `TRUNCATE TABLE place_tags, comments, tags, places` -> `{ ok: true, value: {} }`. Missing tables -> `store_unavailable`. Using `current_database()` (not URL parsing) makes the guard independent of how the connection string is written.

### 1.5 Transaction boundaries

| Operation | Boundary | Isolation / locking | On failure |
|---|---|---|---|
| Listing Save | one transaction for the whole page (all places, all writes) | READ COMMITTED; `pg_advisory_xact_lock(placeId)` for every distinct id, ascending | full rollback, `store_unavailable`; nothing of the page is saved (AC-15) |
| Details Save | one transaction for one place: place row, tag upserts, links, comments, gone marks | READ COMMITTED; `pg_advisory_xact_lock(placeId)`; tag upserts in ascending id | full rollback; the place reads back exactly as before with every Presence Mark (AC-56, AC-58) |
| Invalid input | no transaction, no connection | | nothing touched (AC-15, AC-38, AC-39, AC-51, AC-53 .. AC-55) |
| Multi-query reads (`readPlace`, `readPlaceShapes`) | one read-only transaction | REPEATABLE READ | `store_unavailable` |
| Each migration step | one transaction per step (Knex default) | Knex migration lock table | `store_unavailable`; already-applied steps stay applied |
| `emptyStore` | one `TRUNCATE` statement | ACCESS EXCLUSIVE (implicit) | `store_unavailable` |

The advisory locks make concurrent saves of the same place by two crawl jobs serialize, so the place ends up matching one of the two saves in full (AL6 rule 13). Listing and details saves use the same key (the place id), so they also serialize with each other. No other component uses advisory locks; if a later feature does, it must use the two-key form to avoid clashing with these single-`bigint` keys.

## 2. Data Model Design (Declarative)

### 2.1 General rules

- Absent contract items are stored as SQL `NULL` and are never stored as `''` (AL6 rule 6). Optional text columns carry `CHECK (col <> '')`.
- Text is stored byte-exact in UTF-8 (`text` type, no trimming, no entity decoding; CRLF, Cyrillic, 7,000+ characters are fine; AC-32, AC-33). Known limitation: Postgres `text` cannot hold U+0000; such input would fail as `store_unavailable`. If a crawl ever meets it, report it to AL5 rather than patching AL2.
- Every whole number that comes from Wikimapia is `bigint` (ids, numbers, votes, user ids, epoch seconds), read back through the int8 parser (section 1.4.2). Positions are `integer`.
- Coordinates are `double precision`; the outline copy is `jsonb` pairs. Both round-trip JS doubles exactly (AC-8 uses `toStrictEqual`).
- Presence Marks are `text NOT NULL CHECK (presence IN ('present', 'gone'))`, matching `PresenceSchema` values directly (a Postgres enum type is avoided because it complicates undo).
- No column name may match the structural checks of AC-5 (`embedding`, `vector`, `visited`, `crawled`, `progress`, `cursor`), AC-6 (IP patterns) or AC-14 (`page`, `count`, `found`, `total`, ...). The names below satisfy all of them.
- No `created_at`/`updated_at` columns (nothing needs them, and they would only add churn to idempotency).

Objection: `PlaceModel` with `static override tableName = 'places'`, `static override idColumn = 'place_id'`, `static override jsonAttributes = ['outline']` (Objection stringifies it on write; without this pg would send a JS array as a Postgres array literal), instance columns declared with `declare` (e.g. `declare place_id: number;`; never initialised class fields, which would shadow Objection's values under `useDefineForClassFields`). Geometry properties are typed `string` and are written only with `Knex.Raw` values (Objection's `PartialModelObject` accepts `Knex.Raw` for any column). `details_fetched_at` is typed `string | Date | null` (U9): it is written as the whole-second ISO text `fetchedAt`, a read through the model would get pg's `Date`, and no code reads it through the model (reads use `details_fetched_at_text`, section 1.4.8). With these types, the typed column maps of section 1.3 (`SummaryColumns`, `DetailsColumns`) spread into `insert`/`patch` type-check against the model. Relations: `comments` (HasMany `CommentModel`, `places.place_id` -> `comments.place_id`), `tagLinks` (HasMany `PlaceTagModel`). No Objection `jsonSchema`: validation is done by the contract Zod schemas (`.agrules` section 2), so Objection's AJV validation would only duplicate it.

Self-reference: FK `(place_id, parent_num)` -> `comments(place_id, num)` `DEFERRABLE INITIALLY DEFERRED` (checked at commit; `MATCH SIMPLE`, so a null `parent_num` is not checked). Index `btree (place_id, parent_num)`. There is **no** column for a Commenter IP in any form (no `user_ip`, no `inet`/`cidr` column anywhere; AC-6).

Invariants that keep the reply tree sound: rows are never deleted, so a Gone comment's parent row always exists; the Present comments of a place always form a tree whose parents are Present (they come from one Details Save); a Gone comment keeps the `parent_num` it had when last Present (AC-66, AC-67).

Objection: `CommentModel` (`tableName = 'comments'`, `idColumn = ['place_id', 'num']`, relation `place` BelongsToOne `PlaceModel`; `presence` typed with the contract `Presence`, U9). Inserts take `CommentColumns`, update patches take `CommentPatchColumns` (section 1.3).

### 2.5 Mapping summary (Client value -> columns -> read-back)

- Summary: `placeId`, `name`, `url` -> `wikimapia_url`, `location` -> 6 numbers, `outline` -> `outline` + `outline_shape`, centre -> `centre_point`. Page totals are dropped.
- Details: `title` -> `name`; `location` address items -> `address_*`; `houseNumber` <-> `address_house_number`; `tags` -> `tags` + `place_tags`; `comments` (recursive) -> `comments` rows (flattened, pre-order); `fetchedAt` -> `details_fetched_at`.
- Read-back reverses the mapping exactly (section 1.4.8) and adds `presence` on every tag, comment and reply, `wikimapiaUrl` always, `detailsFetchedAt` on detailed places only.

## 3. Batch & External Calls

This feature calls no external API (no Wikimapia, no OpenAI; AC-62) and runs no batch job. Its only I/O is the local Postgres server.

| Database operation | Unit of work | Timeouts | Retry | Idempotency |
|---|---|---|---|---|
| Listing Save | one Listing Page (at most 100 places) per transaction | connect 5 s, pool acquire 10 s, statement 30 s | none inside the store; `store_unavailable` is returned and the crawl (substep 3) decides | re-saving the same page writes nothing and reports `unchanged` (AC-9) |
| Details Save | one place per transaction | same | same | same details + same moment: no writes (AC-21); later moment: one write, `unchanged` (AC-22, AC-64) |
| Reads | one read-only transaction | same | none | n/a |
| Schema Setup | one transaction per step | same (a step should take well under 30 s on an empty DB) | none | `apply()` skips applied steps (AC-3) |

Crawl guidance (non-binding, substep 3): retry a `store_unavailable` save with exponential backoff, since the save was rolled back completely; skip and log an `invalid_data` save, since retrying identical data cannot succeed.

## 5. AL2 Guidance (toolchain pitfalls)

- Imports: `import knex from 'knex'` (default import, never `import { knex } from 'knex'`) plus `import type { Knex } from 'knex'`; `import pg from 'pg'` (default import, then `pg.types`; never named value imports from `pg`); `import { Model } from 'objection'` (named import is safe: `objection/lib/objection.js` ends in a plain `module.exports = { Model, ... }` shorthand literal, which Node's CommonJS export detection exposes as named ESM exports). Relative imports extensionless.
- **Runtime imports must work under both Vitest and `tsx`/plain Node ESM.** Vitest's Vite interop tolerates named imports from CommonJS packages that Node ESM rejects, so a green test run does not prove a script will load. For any CommonJS dependency without an `exports` map, use the default import unless Node is known to expose the named export; `import type` is always fine. Check by running `pnpm db:status` and `pnpm db:migrate` (`tsx` scripts that load `src/db/`) in addition to the tests. No `type`/`interface` declarations outside `src/db/types.ts`.
- Objection: always `XModel.query(trxOrKnex)`; never call `Model.knex(...)` (several stores with different connections exist at once in the tests). Override statics as properties (`static override tableName = 'places';`), not getters (TS2610), and declare instance columns with `declare` (no initialisers).
- `strictTypeChecked` and `knex.raw`: results are `any`. Assign to `unknown` and parse with a row schema from `rows.ts` on the next line (`z.object({ rows: z.array(XRowSchema) }).parse(result)`); never access members of `any`. This, caught errors and their `cause`, and validator parameters for untrusted input are the only places where `unknown` is allowed (`.agrules` section 5; the full list is the KEEP rows of the section 4 refactor note).
- **No `unknown` stand-ins** (`.agrules` section 5). Column maps are `SummaryColumns` / `DetailsColumns` / `CommentColumns` / `CommentPatchColumns`, generic column comparisons use `ColumnValue`, the pre-gate shapes value is `ShapesCandidate` (all in `src/db/types.ts`). `PlaceStore` methods take the contract input types, never `unknown`, and still call the validators. Write statements are handed to `writer.run` directly, not returned as `PromiseLike<unknown>`. Never write `Record<string, unknown>` for an object whose keys you know. If a value would need a type assertion to narrow, stop and report it.
- `exactOptionalPropertyTypes`: attach optional output keys only when the column is not null; never assign `undefined`.
- Floats: never round, never `toFixed`; equality in the planner is `===` on the numbers as read back.
- Never `console.log`; never copy any error's `message` into a failure; never log or return connection strings.
- Do not use `ST_AsGeoJSON` for read-back coordinates, `ST_MakeValid`, or anything that rewrites a stored outline.
- Do not edit `contracts/` or its fixtures. If a contract looks wrong, stop and report it (`.agrules` section 0, Triggered Bugfixing).
